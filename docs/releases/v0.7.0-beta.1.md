# AgentBell v0.7.0-beta.1 release notes source

> Preparation source only. No tag or GitHub Release has been created.

## Highlights

- Codex action-required notifications for permission, reply, confirmation, and blocked-attention states.
- User-level `PermissionRequest` and `PostToolUse` command Hooks alongside the existing `Stop` Hook.
- An explicit permission notification policy: Off by default, or Always notify for every unique PermissionRequest occurrence.
- Content-free action events on Windows and Android, with localized notification controls and event history.
- A separate Android `agentbell_action_required` high-importance channel for heads-up, sound, and vibration without a full-screen intent or Do Not Disturb bypass.
- Conservative local English and Simplified Chinese classification of explicit requests in completed responses.

## Privacy and control boundaries

The PermissionRequest and PostToolUse Hooks never return an approval decision. They exit with code 0 and emit no stdout or stderr, so the Codex approval dialog remains authoritative. AgentBell does not support remote approval, remote replies, automatic allow/deny, or Codex permission-policy changes.

Codex Hooks do not reveal whether a PermissionRequest is being handled by Auto-review or is waiting for a person. The default Off policy records no permission action event, history entry, Windows notification, or Android notification. Always notify reports request occurrence, not confirmed human waiting, so it can alert for requests Codex later handles automatically. PostToolUse remains a sanitized lifecycle-correlation signal and is not used as an approval-reviewer inference.

Raw Hook JSON, commands, tool input, descriptions, full paths, prompts, user input, full Codex replies, original identifiers, and pairing credentials are not synchronized. Action events contain only stable enumerations, a project basename, irreversible truncated hashes, an event identifier, time, and sequence.

## Compatibility

Protocol version 1 remains unchanged. The new `category`, `actionType`, and `toolCategory` fields are additive. New clients default missing fields to completion semantics; older clients ignore unknown fields and may safely ignore action events they do not understand. Existing pairing tokens and Stop Hook behavior are unchanged.

The source build does not claim exact structured detection of every user-input request. No stable structured input-request `tool_name` was established during implementation, so no guessed PreToolUse matcher or `--codex-input-request-hook` was installed. High-confidence Stop-response classification is the documented fallback.

Codex App Server exposes precise approval messages such as `item/commandExecution/requestApproval`, `item/fileChange/requestApproval`, `item/permissions/requestApproval`, `thread/status/changed` with `waitingOnApproval`, and `serverRequest/resolved`. They are not available to command Hooks, and a second App Server client cannot observe the Desktop client's private connection. This Beta does not use OCR, UI automation, process injection, private-connection takeover, SQLite scraping, or undocumented `approvalsReviewer` behavior.

## Installation and risk

Setup maintains exactly one AgentBell Stop, PermissionRequest, and PostToolUse Hook, preserves unrelated Hooks and `config.toml`, and lets Codex request manual Review/Trust after a definition changes. Uninstall removes only strictly recognized AgentBell Hooks.

Windows binaries without a trusted Authenticode certificate remain an unsigned Beta and may trigger Microsoft Defender SmartScreen. Public Android assets must be release APKs signed with the established long-term release key; a debug APK is not a release asset.
